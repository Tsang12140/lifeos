# LifeOS 项目长期记忆

## 预览服务：必须常开，不要当临时进程清理

**主人的要求（2026-09-16 明确纠正过一次）**：

- `.review/accept-serve.mjs` 拉起的**预览服务（API 3011 + Web 5199）是常驻的**，主人随时会打开 `http://127.0.0.1:5199/` 看效果。
- **任务收尾时不要把它杀掉。** 我曾把它当成"临时残留进程"在结束前 taskkill 掉，导致主人下次进不去 5199，被明确纠正。这是失误，不是稳妥。
- **端口固定，不要换。** 没有特殊理由（如端口被主人自己的东西占用）就一直在 3011/5199；即使需要重启，也在**原端口**拉起。
- 主人自己占用的端口（如 3001）**永远不要杀**。
- 真正需要结束的只是**验收/播种用的隔离实例**（如 3021/5299 的 `photo-grid-serve.mjs`）和**临时 Chrome 进程**。

**判断口诀**：`accept-serve.mjs` = 常驻预览，留着；`photo-grid-serve.mjs` 等带隔离 data dir 的 = 验收用完可收。

## 改动前先勘察、先问

- 设计/规则类工作**先出方案等确认**再动手；主人说"听你的"才是授权点。
- 改动前的只读勘察很有价值：本次「照片上限 6→9」就是先查明**6 只存在于 Web 端一个常量**（API 与 core 都无上限），才敢只动一处。

## 验收要点（详见 AGENTS.md）

- **当前模型读不了图**，视觉验收只能靠 CDP 客观断言（`getComputedStyle` / `getBoundingClientRect` / 元素计数），截图给主人自己看。
- **`transform` 不改变布局盒宽**：用 `translateX` 做元素叠压，元素的布局总宽仍然是「N 个元素的宽度」，会溢出让容器外；而 `documentElement` 的横向溢出可能是 0（页面够宽吃掉了），**光看页面级溢出会漏掉泄漏**。要用负 margin 参与布局，并逐元素对容器边界断言。
- 旋转/变换后的元素**画出来比布局盒宽**（`w·|cos| + h·|sin|`），预留 overhang。
- 跑 CDP 脚本时若要切换视口，**量不同形态前记得 `Emulation.clearDeviceMetricsOverride`**，否则会量到上一个视口的折叠态几何（曾导致 5 项假 FAIL）。
