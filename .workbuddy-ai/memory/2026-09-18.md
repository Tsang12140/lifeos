**症状极其安静**：没有任何报错，密文还在文件里，只是 `decrypt()` 的 GCM 校验失败被 `catch { return undefined }` 吞掉 —— 唯一表现是**设置页显示「未配置」**。

**讽刺的是 `.env` 第 19-21 行早就写了这个坑**（「一旦改了数据目录或密码，已保存的密钥就会静默解不开，建议显式设一个」），但那行是**注释状态**，谁都没设。

### 定位过程（含一次自己的误判）

1. 先离线穷举 7 个路径候选 → **全失败**，差点得出「不是路径派生」的错误结论。
   真因：我用 `node -e` 内联脚本，**bash 双引号把 `\\\\` 折成 `\\`，候选串写坏了**。
   改成写文件 + 用 node 的 `resolve()` 算候选 → **一次命中**。
   → **涉及反斜杠的字符串比较一律写脚本文件，别走 `node -e`。**
2. **决定性实验**：`.review/probe-weather-secret.mjs` —— 用 pre-move 快照副本**把原路径原样重建**，同一份密文跑独立 API(3099)：原路径 `true`、新路径 `false` → 铁证。
   探针注意点：`LIFEOS_ASSET_ROOT` 指向空目录（第二个 API 实例开机跑孤儿资源回收，**绝不能走主人的 `pic-test/`**）、`BACKUP_S3_ENABLED=false`（别往真桶写快照）、跑完删掉重建目录。
3. 反查工具 `.review/find-weather-secret.mjs`：三个密文全部被 `lifeos-local-weather:<搬迁前的数据目录>` 解开。

### 修复

`.env` 钉住 4 个种子（值 = 搬迁前目录派生的串）。选这个而不是「换新密钥+重加密」：**零写入数据文件、零风险弄坏密文**，且种子仍可由那个串推导。
影响面其实只有天气（`ai-config.json` 无密文，movie/backup 配置不存在），但**四个一起钉**。

**`.env` 里那 4 行值嵌着一个不存在的路径，看着像残留，其实是故意钉的密钥种子 —— 删了等于换密钥。**

### 守卫

`migrate-data-dir.mjs` 加了前置检查：**种子没钉住就拒绝搬迁**，且放在**端口检查之前**（配置问题先暴露，别让人白停服务）。
**双向验证过**：`.env` 在位 → 放行；临时藏起 `.env` → 拒绝并列出变量名（测完立即还原）。
