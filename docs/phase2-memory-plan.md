## 2026-10-16 正文检索落地状态

- `apps/api/src/journal-embedding.ts` 从服务端 `.env` 读取 `DASHSCOPE_API_KEY`、`LIFEOS_EMBEDDING_BASE_URL`；当前默认 `text-embedding-v4` / 1024维。`LIFEOS_EMBEDDING_ENABLED=false` 并重启可暂停调用，日期和词法回退保留。凭据全局共用，向量落各档案卡／账号自己的 SQLite `journal_embeddings`，不增加独立向量服务。
- `journal-memory.ts` 仅处理未删除、非私密、非预置的日记正文，1200码点分段、200码点重叠，每批最多10段；最后一次保存后延迟30秒后台调度，连续保存合并，启动补漏也延迟30秒。兜底巡检固定北京时间每天03:00一次，取消每分钟轮询；错过深夜窗口不会在白天追赶巡检。批量后续批次间隔500ms，失败退避60秒后由独立定时器重试，关闭取消请求和迟到写入。配置身份包含地址／模型／维度／输入版本，正文hash命中不重跑；改正文、变私密、删除或替换导入由数据库触发器立即清掉旧向量。改日期等元数据不重算正文。
- `journal-retrieval.ts` 按上海日期范围、明确人物／地点筛选，再融合词法与语义候选；候选最多8篇，每篇最多1200码点。最近6条只作背景，原文不在标识列表中重复传输；篇数从完整可读日记范围计算，不能用top-k估算。实际提供的日记正文才能作为出处，伪造／过期ID拒绝，沿用一次格式修复上限。
- 主对话 `assistant-conversation.ts` 已替换“最近100条就是搜索空间”的前提。出处复用已持久化的只读 `record.focus` offer，实时、刷新、历史均可点；点击先开既有记录预览，保留原页面，不自动导航。没有向量Key或上游故障时回落日期／关键词；没有回答模型Key时列原文并标明本地规则。

## 已完成的基础

聊天由服务端先保存用户消息，再保存结果；稳定的 conversationId/turnId 防止重试重复执行。清屏使用序号边界，只隐藏当前屏幕；新对话显式更换当前会话并解除旧草稿绑定。会话绑定方案，发送固定 revision，避免确认另一窗口后来改过的草稿。历史按日期、关键词与游标翻页，附件保存资产引用，不复制图片数据。

本轮验收：完整 npm test 234 项、隔离浏览器 100 项通过；记录见 .review/assistant-history-reliable-tests-approved-20261010.txt 和 .review/assistant-history-reliable-browser-20261010.txt。

## 纠正原方案的预算前提

不能从正文字符数推断整个请求的 token。此前只读聚合：非私有 156 条正文 4,276 字符，连同 id/revision/日期等的 JSON 已是 23,398 字符；排除预置记录后是 29 条个人非私有记录、正文 1,428 字符、JSON 4,996 字符。还没有算系统提示词、当前问题、材料和会话上下文。

因此废除“正文除以 1.6”“4,800 字符或 180 篇后才检索”和“语料小时每轮全库发送”的规则。当前 assistant-conversation.ts 与 assistant-backfill.ts 的最近 100 条截断仍未替换；它们只能提供近期背景，不能证明找遍旧日记。

## 下一步：按问题查原文，再回答

1. 普通聊天只带必要近期上下文。询问过去事件时，先产生有界检索计划：资料来源（日记/聊天）、上海时区的日期范围、关键词及少量替代表达。明确的日期先用规则解析；模糊情绪或改写需要模型时，检索规划最多增加一轮请求，禁止无限工具循环。
2. 本地数据库先按时间、记录类型和可见性筛选，再以关键词、中文短语及相关人物/地点召回。直接用现有查询或 SQLite FTS5；中文 trigram 对短词和不同说法有局限，必须保留短词回退。词法召回是第一版，不宣称它等于语义理解。
3. 只向回答模型提供少量候选的匹配片段、日期、稳定 id 和 revision。必要时再读取其中几篇原文；最近 100 条不能充当搜索空间。聊天搜索与日记搜索使用不同数据源，不能混为一份记录。
4. 回答的事实带可点击出处，指向具体日记/消息；来源不支持“被骂哭”等细节时，不补写。未检索到只能说本次没有找到，不能断言从未发生。安慰和建议可以继续，但与原文事实分开表述。
5. 没有 AI key 时仍能按日期与关键词查找并列出原文；不伪装成模型结论。默认排除预置与私有记录，私有资料需要明确的访问策略，不能随着索引开启悄悄送给模型。

## 成本、缓存与一致性

- 不每天让模型重读所有日记；读取历史弹窗和本地查询不调用模型。
- 文本索引是可再生派生数据，按 recordId + revision 增量更新；编辑、撤回、删除、隐私变更要立即失效。聊天按 messageId/seq 增量索引。原文始终是权威来源。
- 预算覆盖整个请求，而不是只有检索片段。优先用提供商 tokenizer；不可用时用明确标注的保守估算和余量，并用实际 usage 校准。设置候选数、每篇片段、读取轮数与输出上限，超预算继续缩小或分页。
- 回顾摘要以后按范围与来源 revision 缓存，保留出处。周报/月报不是完成检索的前提，先不额外加入定期模型任务。
- 本地 embedding 是否引入取决于独立评测的实际增益与部署资源。此前 12 条语义查询不是通用准确率，官方 CLS pooling 与 query 指令需验证；不手工删除 npm 平台包作为正式部署方案。本轮未新增模型或推理运行时依赖。

## 再下一步：照片可搜索

先以独立实验验证图文模型和图片描述/OCR的效果。文本 embedding 不能直接理解照片。可采用缩略图一次分析、contentHash 去重、增量处理；存短描述、OCR、模型版本与必要向量，检索后只读取相关媒体。

历史照片回填应是可暂停、有数量/费用上限、可查看进度的任务；新照片按需进入队列。只有来源变化或模型版本升级才重算。云端视觉接口需要明确说明发送哪些图片与费用；本机模型需要评估移动设备兼容性、内存与耗电。视频先基于已有缩略图与配套文字，是否抽帧另外验证。

## 下一阶段的验收门槛

使用隔离数据与独立编写的查询集，覆盖：去年六月、去年年终、换种说法的情绪事件、多个相似事件、无结果、跨上海午夜、长篇、旧记录、撤回/私有记录、跨账号与索引过期。每个命中可回原文；同时记录实际输入/输出用量、召回质量、延迟与内存。不往 3011/5199 写测试日记，不把实验分数当真实资料检索保证。

## 归档的后续边界

SQLite/整实例备份会带上聊天表；现有便携空间导出白名单没有聊天表（portable-space.ts 的 SPACE_TABLES）。下一阶段需确定便携导入/导出如何携带聊天与附件、如何处理旧草稿绑定，再做带版本号且向后兼容的格式变更。当前没有改动该格式，也没有自动迁移早期 assistant_batches.conversation 为分段归档。
