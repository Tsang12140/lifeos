# 单空间完整加密包 v1

设置页按需生成 `.lifeos` 包，下载到用户电脑。服务器不把这个包另存对象存储；原件在存储池时，读取仍计入项目及用户下载流量。此包迁移当前空间的业务内容，不迁移账号、身份主密钥、会话、集成凭据、存储池账本、定时任务或浏览器偏好。整站恢复继续使用管理员整卷工具。

## 字节格式

所有整数为大端序。加密外壳固定为：

| 顺序 | 长度 | 内容 |
| --- | --- | --- |
| 1 | 8 bytes | ASCII `LIFEOS01`，标识格式版本 |
| 2 | 16 bytes | 每个包独立随机 salt |
| 3 | 12 bytes | 每个包独立随机 IV |
| 4 | 可变 | AES-256-GCM 密文 |
| 5 | 16 bytes | GCM authentication tag |

密钥由原始密码字符串与 salt 通过 scrypt 派生：`N=131072, r=8, p=1, dkLen=32, maxmem=256 MiB`。前 36 bytes 全部作为 AAD。密码长度 10–1024 个 JavaScript 字符，不 trim、不做 Unicode 归一化。账户导出先验证当前账号密码；本地无密码实例自设包密码。口令未落盘，派生 buffer 用后清零，但 JavaScript 字符串不能承诺安全擦除。服务器处理口令与明文，此方案保护导出文件，不能隔离正在运行的应用服务器。

解密后的 payload：4 bytes 清单长度、UTF-8 JSON 清单、按清单顺序串联的原件字节。不压缩；不存在可执行脚本、tar 路径或用户指定输出路径。清单最多 32 MiB，完整文件最大 20 GiB，原件数量最大 100000。

清单结构：`{format:"lifeos.space",version:1,exportedAt,tables,files}`。业务表白名单为 records、entities、assets、asset_trash、day_summaries、cycle_intimacy_module、cycle_intimacy_events、weather_device_locations、weather_day_cache、weather_observation。每个表携带固定列名与逐行值；目标列必须完全匹配，不兼容版本拒绝导入。私密与软删除记录保留；仍可恢复的回收站资产包含原件，已经清除的回收站历史不含原件。

`files` 的每项为 `{assetId,trash,bytes,sha256,mediaType}`。原件缺失、大小变化或已知 contentHash 不匹配时整个导出失败；不能以成功下载掩盖缺失文件。

## 导入和并发

上传与解密在私有临时目录进行，GCM 最后认证通过才解析清单。依次验证 schema、模型、行 ID、文件索引、大小、SHA-256 和 payload 精确长度，并在一次性数据库里演练业务表替换。预览阶段不写目标业务数据；目标指纹在此时记录。

用户明确确认替换后，先创建 `lifeos-before-import-<UUID>.sqlite` 当前一致性快照并记录到备份历史。新本地原件写入 `uploads/archive-<UUID>/`，回收站原件写入对应 `_orphan-trash` 路径；验证实际父目录不越过资产根，不覆盖旧原件。存储池空间为新资产逐件预留并上传，确认可读后才发布数据库引用。旧原件保留，因此云端导入可能需要容纳新旧两套原件的额度。

业务表在单一 `BEGIN IMMEDIATE` 事务下再次比较目标指纹并替换；预览后的并发编辑会拒绝覆盖。导入失败只撤销本次新文件/新对象；远端删除状态不明时保留账目供管理员核对，不释放无法确认的占用。导入不会改目标账号或集成密钥。撤销令牌与待办派生简写清除，导入后的正文、周期和手写小结保留。

每空间一次处理、最多三个临时任务，全实例最多两个并发处理。临时任务在创建后 15 分钟失效；关闭窗口会尝试取消，后台每分钟清理符合专用名称且过期的非符号链接目录。下载需当前空间认证、有效任务 ID；不提供跨空间列举。生成前检查临时空间与存储池流量，下载响应返回准确 Content-Length。实际公网反代需支持大文件上传与处理时长，仓库隔离验收不能替代目标服务器验证。

## 原有格式

原有 `.sqlite` 手动/定时本地与对象存储备份、JSON/Markdown 导出没有改成这个协议。它们不会因新增入口自动获得全原件加密。自动云端加密、增量去重、长期保留政策仍见 `docs/todo.md` §17 与 §30。不要用单空间完整包冒充包含 identity 与全部租户的整站恢复包。
