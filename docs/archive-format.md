# 单空间完整加密包 v2

设置页按需生成 `.lifeos` 包，下载到用户电脑。服务器不把这个包另存对象存储；原件在存储池时，读取仍计入项目及用户下载流量。此包迁移当前空间的业务内容，不迁移账号、身份主密钥、会话、集成凭据、存储池账本、定时任务或浏览器偏好。整站恢复继续使用管理员整卷工具。

导出默认全量，也可只勾选日记、任务、事件、笔记、人物地点、手写小结、周期或全部照片原件，并可限定 `from`/`to` 日期。被勾选记录引用的照片原件会自动带上，即使未勾「照片」分类。v2 包导出的是一份**快照**：内容不随原空间后续编辑更新。

## 字节格式

所有整数为大端序。加密外壳固定为：

| 顺序 | 长度 | 内容 |
| --- | --- | --- |
| 1 | 8 bytes | ASCII `LIFEOS01`，标识格式版本 |
| 2 | 16 bytes | 每个包独立随机 salt |
| 3 | 12 bytes | 每个包独立随机 IV |
| 4 | 可变 | AES-256-GCM 密文 |
| 5 | 16 bytes | GCM authentication tag |

密钥由原始密码字符串与 salt 通过 scrypt 派生：`N=131072, r=8, p=1, dkLen=32, maxmem=256 MiB`。前 36 bytes 全部作为 AAD。密码长度 10–1024 个 JavaScript 字符，不 trim、不做 Unicode 归一化。账户导出先验证当前账号密码；本地无密码实例自设包密码。口令未落盘，派生 buffer 用后清零，但 JavaScript 字符串不能承诺安全擦除。服务器处理口令与明文，此方案保护导出文件，不能隔离正在运行的应用服务器。

解密后的 payload：4 bytes 清单长度、UTF-8 JSON 清单、按清单顺序串联的原件字节。不压缩；不存在可执行脚本、tar 路径或用户指定输出路径。清单最多 32 MiB，完整文件最大 20 GiB，原件数量最大 100000。

清单结构随格式版本变化，外壳与加密参数不变：

| 版本 | 清单 |
| --- | --- |
| 1 | `{format:"lifeos.space",version:1,exportedAt,tables,files}` |
| 2 | `{format:"lifeos.space",version:2,exportedAt,selection,tables,files,records}` |

`selection` 为 `{categories:string[],from?:string,to?:string}`（日期 `YYYY-MM-DD`）；`records` 为 `{id,fingerprint}[]`，指纹是规范化正文、发生时间（缺失时用创建时间）、人物地点名称与照片 sha256 的 sha256，导入时逐条复核，文件被改过就拒绝解析。

业务表白名单为 records、entities、assets、asset_trash、day_summaries、cycle_intimacy_module、cycle_intimacy_events、weather_device_locations、weather_day_cache、weather_observation。每个表携带固定列名与逐行值；目标列必须完全匹配，不兼容版本拒绝导入。私密与软删除记录保留；仍可恢复的回收站资产包含原件，已经清除的回收站历史不含原件。

`files` 的每项为 `{assetId,trash,bytes,sha256,mediaType}`。原件缺失、大小变化或已知 contentHash 不匹配时整个导出失败；不能以成功下载掩盖缺失文件。

## 导入和并发

上传与解密在私有临时目录进行，GCM 最后认证通过才解析清单。依次验证 schema、模型、行 ID、文件索引、大小、SHA-256、记录指纹和 payload 精确长度。预览阶段只读：v2 包生成合并计划（新增、已有、冲突、悬空引用、原件写入或复用），不写目标业务数据；目标指纹在此时记录。

v2 默认增量导入，只增不删、只增不改：记录先按 id 判重（同 id 且同指纹跳过，同 id 但指纹不同记为冲突并保留目标那份），再按内容指纹去重；人物地点按「类型 + 名称」复用，照片按 SHA-256 复用、不重复写盘；引用了未随包携带的对象会在写入前剥离并计数。冲突只列清单，绝不覆盖目标。v1 包没有选择集与指纹，只能整体替换；v2 全量包既可增量导入，也可在明确确认后整体替换；部分导出的 v2 包只能增量导入。

增量导入在写入前创建 `lifeos-before-merge-<批次 UUID>.sqlite` 快照并记录到备份历史，原件写入 `uploads/archive-<批次>/`（回收站原件写入对应 `_orphan-trash` 路径），存储池按已存在内容复用或先预留上传。业务行在单一 `BEGIN IMMEDIATE` 事务里再次比较目标指纹后插入；预览后的并发编辑会拒绝导入。失败只撤销本次新文件与新对象。

每次成功的增量导入在 `data/archive-batches/<UUID>.json` 记录新增行指纹、原件路径与云端对象键。撤销按整批进行：任何一条新增行被改过，或已被后来的新记录、关系、文件夹引用，就拒绝撤销并列出前几项；通过后删除本批新增行以及不再被引用的原件，并标记该批次已撤销。撤销不改动备份历史里的快照。

整体替换沿用 v1 行为：先创建 `lifeos-before-import-<UUID>.sqlite`，新原件逐件写入且不覆盖旧原件，旧原件保留；业务表在单一 `BEGIN IMMEDIATE` 事务下再次比较目标指纹并替换。导入不会改目标账号或集成密钥。撤销令牌与待办派生简写清除，导入后的正文、周期和手写小结保留。

密码：有账号密码的实例导出时验证当前账号密码并用它加密；本地无密码实例自设 10–1024 字符的包密码（两次输入）。导入始终使用生成该包时的密码，与应用锁的 4 位 PIN 无关。

每空间一次处理、最多三个临时任务，全实例最多两个并发处理。临时任务在创建后 15 分钟失效；关闭窗口会尝试取消，后台每分钟清理符合专用名称且过期的非符号链接目录。下载需当前空间认证、有效任务 ID；不提供跨空间列举。生成前检查临时空间与存储池流量，下载响应返回准确 Content-Length。实际公网反代需支持大文件上传与处理时长，仓库隔离验收不能替代目标服务器验证。

## 原有格式

原有 `.sqlite` 手动/定时本地与对象存储备份、JSON/Markdown 导出没有改成这个协议。它们不会因新增入口自动获得全原件加密。自动云端加密与长期保留政策仍见 `docs/todo.md` §17 与 §30。不要用单空间完整包冒充包含 identity 与全部租户的整站恢复包。
