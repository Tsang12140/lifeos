# 移动端结构重构执行计划

> 主人于 2026-09-20 确认执行。实施：Luna（max）。本文件是本轮唯一的移动端范围契约；完成后保留在本地 `docs/` 供后续接手。

## 目标与非目标

将窄屏（`max-width: 900px`，重点 360 / 390 / 430px）从「桌面顶部与浮动卡片的压缩版」重构为稳定的移动信息架构：实体底栏、无重叠天气、编辑框内提交，以及纵向周历。

- **在范围内**：移动底栏 / 更多菜单、顶部天气、移动搜索入口、移动编辑器底部动作行、移动周历。
- **明确不改**：月历 DOM、月历样式与月历算法；桌面（>900px）导航、天气、编辑器、周历；照片选择与取样算法、上传/保存 API、数据模型。
- **不触碰**：`data/`、任何生产写入、seed 或清理。

## 1. 单行实体底栏

### 信息架构

仅在移动端显示以下 5 项，顺序不可变：`今天 / 日历 / 笔记 / 联系人 / 更多`。

- `联系人` 打开现有 `entities`（联系人与地点）页面。
- `更多` 打开现有 `MobileMenuDialog`，其中只列出未固定项：`时间轴 / 任务 / 时光机 / 设置`。不要让已固定的 4 项在更多里重复。
- 当前处于任一收纳页面时，`更多` 显示 active 状态；`aria-current` 仅用于实际当前页的项目。
- 删除顶部三横按钮的 JSX；不可以只 CSS 隐藏并留下无意义的键盘焦点。

### 几何与视觉

在 `max-width: 900px`：

- `position: fixed; inset: auto 0 0;`，单行 5 等分。
- 不透明纯色背景、只保留顶部边线；`border-radius: 0`、无 box-shadow、无 backdrop-filter，不留左右或底部缝隙。
- 内容区域底部 padding 必须不小于底栏实际高度 + `env(safe-area-inset-bottom)` + 16px。用一个可复用 CSS 变量表达，禁止再用魔法数 `90px`。
- 每项的实际可点击高度至少 44px，包含安全区后的整体视觉高度建议 64px。

## 2. 移动天气卡

### 结构

保留 `WeatherHeader`，移动端采用两列同一行的稳定布局：日期在左，天气摘要在右；不再用 absolute summary 覆盖日期。

- 日期组保留「前一天 / 放大的日期翻页器 / 后一天」；390px 也不可隐藏两个步进按钮。日期输入及其 label 的可点击区域不能被其他元素覆盖。
- 天气组显示地点、天气文字、温度；地点可以省略号但不可整块 `display:none`，天气文字不可在 390px 隐藏。
- 移除可见的刷新按钮及其为避让搜索而加的 margin。用天气摘要区域作为手动刷新入口；日期、日期选择器、前后一天按钮的点击必须排除在刷新之外。
- 不将嵌套互动元素包进 `<button>`。采用合规的命中逻辑或独立无障碍刷新目标；键盘/屏幕阅读器仍有可发现的刷新方式。
- 成功手动刷新调用全局 toast，文案为「天气已刷新」且为成功色；限流和失败给 warning。自动的半小时读取、天空渐变和历史日期逻辑保持。

### CSS 收敛

合并目前多处移动 `.weather-header` 覆盖，最后只有一组 900px / 560px / 390px 的明确规则。不要遗留先宽 48px、后 100px、再 94px 的相互推翻规则；禁止 summary absolute 定位和搜索按钮覆盖天气。

## 3. 搜索入口

移动端不再在顶部天气卡上浮动搜索。

- 给记录 `Composer` toolbar 的右上角加搜索图标入口，适用于日记、任务、事件、笔记 4 种 kind，复用现有 `SearchDialog` 与状态，不复制搜索逻辑。
- 未显示 Composer 的移动页面（例如设置或收纳页）在「更多」对话框提供“搜索记录”入口，保持搜索可达。
- 宽屏继续使用原有 topbar 搜索，不作视觉回归。

## 4. 编辑器内保存与照片动作行

移动端保存按钮不再从 `.composer-footer` 独占整行。

- 把提交动作移动到 `composer-entry` 的右下角动作行，与“+ 照片”同为 44px 高的紧凑控件；按钮不可全宽。
- 小照片 / 添加照片保持在左侧可横向浏览；`n/9`、清空与上传忙态移到保存按钮左方，不能挤压保存或遮住图片。
- 大量照片仍最多 9 张、可移除、能上传、保存后清草稿；只改变移动视觉顺序，不能改变资产/草稿行为。
- 桌面保留现有 composer footer 的保存布局。

## 5. 移动周历：纵向横卡 + 左右拼图

仅在移动端重构 `week` mode：

- 取消横向滚动的 `.week-grid`，改为从周一到周日的 7 张单列全宽圆角横卡。
- 每天卡片是横向矩形：左侧为星期、日期、摘要和记录数量；右侧为当天照片区域。无照片时保持干净的中性空态。
- 保持既有 `dayPhotoIds()` 取样及至多 4 张限制，保持同一缩略图 URL。不新增下载。
- 照片从当前上下横条分段改为左右并列的纵向分栏拼图；可用 CSS variables 提供图片 index/count，让 desktop 继续沿用旧的上下构图。
- 月历完全不动（包括 JSX、选择规则与移动样式）。

## 6. 验收与安全

先 `node .review/data-inventory.mjs` 只读盘点。所有浏览器验收必须新建隔离 profile，不 POST 主人 API。

至少覆盖 360、390、430、768、1024px：

1. 移动底栏恰好 5 个可见项目、单行、`bottom=0`、无圆角/阴影/blur、computed alpha 为 1；主内容最后一项不落在导航下。
2. 更多菜单只含 4 个收纳入口并可到达，顶部三横不存在；Composer 与更多菜单均可打开 SearchDialog。
3. 390/430 天气日期 / 地点 / 天气 / 温度 / 前后步进无矩形重叠；天气摘要点击触发一次手动天气请求和成功 toast，点击日期/步进不触发该请求。
4. 移动编辑器保存按钮非全宽、44px 高、位于照片行右侧；照片计数/清空在其左，保存与上传/草稿逻辑不回归。
5. 周历精确 7 张、单列、每张宽度接近内容宽度、没有水平滚动；存在多张照片时拼图的横向列数等于图片数；月历结构/核心 computed values 与改动前保持一致。
6. 1024px / 宽屏不会出现移动底栏或 Composer 内保存布局。
