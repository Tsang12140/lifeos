# LifeOS 界面设计规范与主人偏好

更新：2026-10-13。维护：Codex。适用于正式 Web 界面、手机适配及设计 Demo。

## 使用方式与依据

这份文件整理主人已经确认的设计选择，供后续开发直接遵循。它不是一次全站改版授权，也不表示所有旧页面已经符合规范。

- **协作与强制约束**仍以根目录 [AGENTS.md](../AGENTS.md) 为准；本文件承接 UI 设计细则与偏好，不另建一份协作规则。
- **已定案**可以沿用；改变规则需先讨论。**偏好**用来判断新方案，不自动变成所有组件的强制尺寸。**仅 Demo／待确认**不能当成正式功能已经完成。
- 同一事项以主人最新明确决定为准。聊天里的助手建议、试验参数和被否定版本不能覆盖后来的修订。
- 设计来源见文末。这里保留结论和可定位的来源，不复制整份聊天记录、私人日记或图片。

## 1. 总体方向：内容优先，克制但可辨

**已定案的方向**：把空间交给正文，减少重复标签、重复说明、装饰框和固定提示。一次操作尽量用一个清楚的入口表达。

**主人偏好**：紧凑、自然、有清楚的对齐关系；适量留白和淡阴影可以有，但不能出现“字很小、空白很多、控件比内容多”。“有设计感”不等于增加曲线、刻度、光晕或另一层边框。

克制也不能造成看不清。操作勾选、必要图标和关键状态必须有足够的轮廓、尺寸及对比度。主人曾明确要求加重标注勾选，同时弱化已完成的提示文字；这两项各自成立。

## 2. 信息层级与文案

- 同一区域不叠“删除记录／确定要删除这条记录吗”这类重复标题，也不在人物卡同时写“人物卡片”和“人物”。
- 固定说明只有在帮助用户完成当前判断时才显示。实现过程、API 校验流程、泛泛的安全保证，不常驻在普通操作界面。
- 错误在实际失败时出现，并提供可执行的下一步；不能用一屏防御说明替代可靠的处理逻辑。
- 已确认的状态退为灰色、普通字重。例如“检查标记”核对完成后使用灰色和 400 字重；出现新候选才恢复提醒。
- AI 与日记正文输入框保持空白，不放教学式占位文案；必要字段名称、单位和配置说明放框外。此项不能机械扩成所有输入框都禁止合理提示。
- 自有界面文案不用间隔号 `·` 连接短语。用户原文、书名及有语义的专名不按界面分隔符处理。
- 空白日历卡不写“没有记录”或“—”；查询无结果、读取失败、加载中必须有可区分的状态，不能把所有空状态都删除。

## 3. 字体与颜色

| 用途 | 当前约定 | 范围与注意事项 |
|---|---|---|
| 默认字体 | MiSans，保留系统字体回退 | 使用现有 `LifeOS MiSans` 字重映射，不凭裸家族名推断实际字重；不擅自新增字体选项 |
| 日记正文 | `#4D5869` 灰蓝 | 主人从 Demo 选定的阅读色，不把所有标题、按钮一并改成这个颜色 |
| 次要说明 | `--muted` | 比正文轻，仍需清楚可读 |
| 人物正文胶囊 | 中性灰、圆角矩形 | 人名属于句子，不用亮蓝把它做成抢眼链接；复用 `--chip` 系列 |
| 删除等危险操作 | `--danger`，当前 `#BA4D5A` | 用颜色和文案表达，不靠按钮更大或附加大图标 |
| 任务侧栏数量 | 18px、`#566274` | 右边缘与正文共线，位数增加向左长；只适用于该数量组件 |
| 标注核对的地点／总开关 | 当前中蓝色 `#4B86D5` | 主人为可操作性确认的局部颜色；正文人物胶囊仍保持中性 |

主人明确不喜欢任务数量用亮蓝。由此形成的偏好是避免无处不在的蓝色强调，而非禁止全产品使用蓝色。角色、选中状态和核对操作仍可使用既有语义色。

其他基础色、圆角、阴影优先复用 `apps/web/src/styles.css` 的现有变量，不另造一套近似色。普通正文不靠大面积粗体表达层级，状态和说明尤其避免持续高字重。

## 4. 按钮、间距与网格

同组按钮的完整强制要求见 [AGENTS.md 的“按钮层级与尺寸”](../AGENTS.md)。设计时重点执行：

- 同组主、次、危险按钮共用高度、字号、行高、内边距和圆角；仅颜色、描边、文案、顺序表达优先级。
- 普通组整体 40px，紧凑组整体 34px；不用单独增高、加宽或拉满主按钮。
- 间距归容器：用 `gap` 和区域 `padding`，不在基础按钮优先级类里塞外边距。
- 边缘与分隔线留至少 8px；自然换行时对整组处理，不只拉满一个按钮。
- 标题、数量、正文、状态和操作尽量共用对齐线。验实际文字／图形中心和右边缘，不只比较按钮外框。
- 一个局部组件的参数不是全站尺寸规定。侧栏数量 18px、头像 160px 派生图、时间轴点 7px，各自在其用途内生效。

## 5. 弹窗与原地查看

**已定案**：查看相关日记先用弹窗保留上下文；用户主动“进入原记录／进入时间轴／进入当天”时才导航。

- 人物／地点相关日记、管理页最近与全部记录、首次关联日记、AI 当前批次辅记共用记录预览逻辑；保持原页面、筛选、滚动位置和聊天草稿。
- 预览能读完整内容和看照片，编辑、删除、任务状态修改留给原记录操作界面。
- 原生弹窗外侧空白点击收起，不确认、不删除、不透点底层；内部点击和从内部拖出不算外侧点击。
- 多层查看一般逐层返回，关闭后焦点回到来源入口；共享滚动锁，防止同时退出后页面还不能滚动。
- 忙碌／草稿等既有关闭语义继续遵守。AI 历史的日期浮层、笔记 Escape 的草稿提示等已有特例，不能强行变成所有弹窗按 Escape 都无条件关。
- 内容较长时正文滚动，关键操作可见。不要给所有小弹窗统一套大标题、大间距和分隔层。

实现参考：`record-peek.tsx`、`calendar-day-dialog.tsx`、`dialog-dismiss.ts`、`dialog-scroll-lock.ts`。

## 6. 单条记录删除确认

**本轮已定案并实施**：

```text
删除这条记录？

最多两行的记录摘要……

                       取消  删除
```

- 360px 宽度上限，随窄屏收缩；标题正常字号，摘要轻灰，最多两行。
- 去掉重复小标题、固定备份说明、摘要套框、垃圾桶装饰及多余分隔线。
- 两个文字按钮同为 34px；取消中性灰，删除沿用危险色。
- 默认焦点在取消，每次打开都重新设置；忙碌防重复，失败留在原处并显示实际错误，成功才收起。
- 这个模式适用于日记、任务等**单条记录**确认。整库替换、迁移、批量删除等范围不同，不据此删除真实影响范围的必要说明。

实现参考：`dialogs.tsx` 的 `ConfirmDialog`、`styles.css` 的 `.record-delete-dialog`。不要用修改通用 `.confirm-dialog` 的方式误改导入弹窗。

## 7. 时间轴与任务

- 时间轴采用主人选定的 **C 细空心环**：7px、1px 灰蓝边框 `#8997A6`，纸色内底；无蓝色内芯、外圈和光晕。
- 时间与轴点共用首行垂直中心；轴线对准环的横向中心，时间使用等宽数字。长卡片不把圆点挪到整卡中间。
- 正文已有的人物／地点不再在底部重复堆标签。后来增加的地点资料卡是独立查看入口，位于照片之后的底栏，不要按旧的“删除重复标签”规则再次删掉它。
- **任务左上角黄色类型标签保留**。曾经删除是主人明确纠正的过度改动。
- 任务类型标签在上、正文在下，左边对齐并使用整行宽度，这是 2026-10-12 的后续修订。已完成正文默认单行省略，点击展开／收起；完成状态与操作仍共用底栏。不能按更早的“两行卡”方案把类型和正文重新并排。
- 待办正文保留全文，高度随内容自然增长；状态与操作共用底栏，不用最小高度制造空白。

## 8. 右侧任务栏与完成反馈

- 长任务默认最多两行，点击正文展开／收起；正文与圆圈对齐首行，不对齐整段中心。
- 标题、数量和正文共享网格；细灰滚动条约 6px，悬停可加深，不使用醒目的粗滚动条。
- 待办为空心圈。**保存成功后**才显示淡绿画勾、短暂停留、再收起任务行；保留撤销。失败不能假完成。
- 铃铛使用主人选定的 SVG；空状态灰色空心，有未完成任务叠 6px 红点，同一铃铛的大小、位置、颜色不随状态跳动。
- 数量与正文右边缘对齐；动画以右侧为锚点，不把数字弹到网格外。

参考：`task-summary.tsx`、`task-notification-icon.tsx`、`task-summary` 相关样式。

## 9. 人物、地点与标注核对

- 卡片头部优先“头像、姓名、星星”；有实际关系才显示关系，没关系不造通用“人物”徽标。
- 收藏直接点星星，不增加“重要联系人”文字或勾选字段。未收藏灰色空心，收藏整颗淡黄；姓名与星形视觉中心对齐。
- 头像使用圆角方形，右下角叠既有编辑图标；裁切、缩放后保存适用尺寸，同一头像地址共用缓存。
- 常用联系人依据关联记录热度和时间衰减展示，收藏保留展示资格；不常用不等于“不重要”，全部列表与搜索仍可找到。
- 日记保留当时称呼，身份按稳定 ID 关联。改资料或删别名不暗改历史正文，也不改变已确认归属。
- 核对以实际排版最多两行一个单元；相邻词可共用上下文，每次出现仍独立选择。
- 左侧总开关有全选／部分／全不选三态，完整圆角外框；词旁勾选与类型图标复用既有系统，轮廓必须清楚，不能像 disabled。
- 前后渐隐突出待核对词，展开后读全文；普通上下文点击展开／收起，关键词和勾选只切换关联。删除多余“展开完整上下文”文字。
- 输入框确认后的词保留轻底色，不再追加一排名单；光标编辑与资料查看分清。
- 地点电话使用普通 13px 灰字，无醒目下划线；地图、拨号作为明确操作。精确收录时间和首次日记放在默认折叠的档案里。

**仅 Demo 已选型**：重名人物附注用 A 小括号、字号为称呼的 80%。取名权重、避重名与稳定规则仍需单独确认／接入；不能把 Demo 通过写成正式算法已上线。

## 10. 搜索与筛选

- 保留谷歌式药丸／聚焦搜索的方向，与日记／任务工具区整合。旧 48px 常驻大搜索栏不是现行桌面默认规格；当前紧凑入口约 34px。
- 人物与地点选中后形成可删除／替换的胶囊，文本关键词和实体关联条件含义分清；AI 不能靠猜测把普通字自动变成人物。
- **每个已选实体胶囊都必须满足**。早期“同类人物任一即可”的规则已被纠正；其他维度按对应筛选语义处理，不把这句话泛化成所有类型选项都必须同时成立。
- 全部符合与接近结果分开；接近结果按满足条件数排序，同分按记录时间倒序，明确缺少什么。用户移除条件后才真正改变筛选。
- 结果少于 3 条时用轻量提示引导问 AI，不盖住结果，不弹强制引导。
- 桌面筛选优先向上自然增长，空间不足再向下；窄屏随页面展开。这个面板不嵌套内部滚动条，不能扩成全站禁止滚动。
- 搜索、筛选和零结果不收掉右侧任务／AI，也不丢已有聊天及草稿。

参考：`record-search.tsx/.css`、`search-filters.tsx`、`search-alternatives.tsx`。

## 11. 日历、照片背景与天气

- 周卡按既定规则：1 图铺满，2–4 图分段，超过 4 图取第一、最后和中间均匀样本，不预告剩余张数；月历格只用算法选出的 1 张。
- “照片做底纹”是铺满整卡／整格，不是底部一条。白蒙版用于文字可读，必要时降低照片存在感。
- 没记录保留纸色和日期大字；有文字没图去掉日期大字；有图沿用照片背景。正文、待办、小结都算内容，过去／今天／未来一致。
- 周历日期大字竖排，本周与上一周同规则；未来日期不能点击或键盘进入，即使已有待办。
- 月历不放固定“法定休息／调休上班”图例；实际日期标记继续保留。
- 月历工作区照片墙使用主人选定的齐边拼贴默认值：12 张、白蒙版 92%、阴影 60%、白边／间距／倾斜均 0、排布 1；这些是可自定义参数，不是禁止用户调整。
- 照片墙随页面滚动，高度不足可重复铺同一缓存拼图，右侧铺满工作区。汉字底图不计入 12 张真实照片门槛；查看期间不后台换图。
- 天气卡左右、底部圆角外不多出矩形留白；上方遮挡保留且轮廓连续，不能漏上圆角或拼出阶梯边。
- 太阳／月亮优先简单、随宽度自然变化的定位；不为轻微重叠制造一串特判断点。此前多次轨迹试调不应写成多个并存方案。

## 12. 桌面、手机和动效

- 桌面右栏与各页标题／输入区有明确对齐锚点。任务卡先保持顶部对齐，AI 内容从下方向上长，空间不足再共同抬升。
- AI 内容少时的起始上沿对齐保存按钮；内容多时可增长并内部滚动。手机使用独立入口，不硬塞桌面右栏。
- 手机 AI 入口去掉外圈、白底和阴影，默认稍透明，操作时清晰；保留触摸热区、拖动与位置记忆。
- 返回顶部保留主人选定的图标、柔和细边和淡阴影；桌面 44px、手机 48px。手机由 AI 向上避让回顶，净距约 12px。
- 图标优先复用现有库或主人选定 SVG，不临时乱画；不能只取一个模糊像素图，也不能把所有组件都替换成同一图标风格。
- 动效用于说明完成、展开和位置变化；不过度弹跳／放大。回顶可由滚轮／触摸中断，遵循减少动态效果偏好。
- iPhone 选完照片立即收起自定义抽屉，上传进度留在输入区；不要让上传等待卡住选图流程。

## 13. 文本选择、隐私与性能

界面文字／表单／正文的选择性要求以 [AGENTS.md](../AGENTS.md) 为准：默认不可选，仅正文和值叶子可复制，不能为了复制内容把整个卡片放白名单。原生顶层 dialog 需核对计算样式。

图片展示复用同 URL 和适当缓存；缩略图、头像、照片墙不能为同一次查看额外重复下载原图。性能目标与实际实现要分开描述，不凭旧文档断言所有缩略图现在都直连原图。

隐私显示、隐藏预置记录、账户空间等现有边界在预览和搜索中一致执行；UI 简化不等于省略授权或改写数据语义。无 AI Key 时保留规则回退，不让基础记录和查看依赖 AI。

## 14. 交付前的最小设计核对

1. 是最新已定案方案，还是旧提案／仅 Demo？是否误删了主人明确保留的组件？
2. 内容与标题有没有重复？是否有不帮助当前操作的固定说明、套框和徽标？
3. 实量同组按钮高度、纵向中心、外边距及距分隔线净距；不能只验 CSS 声明。
4. 覆盖桌面、320／390px 窄屏、长文、换行、自定义字号、短视口及实际忙碌／失败状态。
5. 用真实点击／键盘检查关闭、焦点、原地返回、照片与嵌套弹窗；动画成功时机和中断要验证。
6. typecheck、npm test 与对应 CDP 验收通过，结果落 `.review/*.txt` 并以 `RESULT: PASS/FAIL` 结束；写入验收只用隔离实例，不截图冒充证据。
